## NS-001（P1）：还原"默认测点"公式与创建时规范公式不一致

### 问题
最近提交 9367fc47 引入的"重复测点拒绝后还原为默认测点"逻辑，以及右侧面板【默认】按钮，其默认测点公式固定为：

```
节点ID[.端子ID].量测类型ID
```

而创建量测项时的规范默认测点（`measurementSourcePointForNodeItem`）为：

```
节点ID[.端子ID].(associatedField || (role ? "role." : "") + 量测类型ID)
```

当设备量测 profile 配置了 `associatedField`（如 `Ua`）或 `role` 时，两个公式产生不同结果。

### 发现位置
- `src/appExtracted/appGraphMeasurementFactories.tsx:4583` — 还原分支 `defaultSourcePoint = ${nodeId}${terminalId ? `.${terminalId}` : ""}.${measurementTypeId}`
- `src/appExtracted/appGraphMeasurementFactories.tsx:5117-5119` — 【默认】按钮同公式
- 对照：`:4439-4440`（规范公式）、`:4474-4478`（创建时调用）

### 证据（已用临时测试复现，跑后已删）
用 profile `{measurementTypeId: "activePower", role: "measure", associatedField: "Ua"}` 创建的项，规范默认测点为 `node-a.t1.Ua`；将其编辑为重复测点后被拒绝还原，结果为 `node-a.t1.activePower` —— **原绑定被覆盖为一个从未是"默认"的值**。

### 风险
1. 一次被拒绝的重复修改即永久丢失原默认绑定（undo 快照可回退，但用户难以察觉）。
2. 同组两个同量测类型项（`createMeasurementItemForNode` 的 `?? profileItems[0]` 兜底允许此情况）还原出相同默认测点 → 重新制造查重要阻止的重复。

### 为什么不能自动修改
- 哪个公式是权威"默认"是产品决策：【默认】按钮 title 与占位符明确写的是"节点ID.端子ID.量测类型"，简化公式可能是**有意的**。
- 若改为规范公式，需要按 item 反查 profile 的 `associatedField`/`role`（binding 上未存 associatedField），涉及新增数据查询路径，无法证明 100% 无副作用。
- 该区域是用户最近 5 次提交正在迭代的代码，擅自改动易与进行中的工作冲突。

### 人工处理建议
确认权威默认公式后二选一：
- 以创建时公式为准 → 还原分支与【默认】按钮改用 `measurementSourcePointForNodeItem`（从 profile 反查 role/associatedField），并补单测；
- 简化公式是有意的 → 建议在 UI 文案与文档中说明其与创建默认的差异，并考虑还原前校验还原值自身是否重复。

推荐优先级：**P1，建议尽快决策**。

## NS-002（P2）：量测编辑弹窗确认不查重测点

### 问题
`createConfirmMeasurementEditorDialog` 确认时仅校验名称重复，未校验测点 `sourcePoint` 重复；右侧面板编辑与保存合规校验均已覆盖测点查重，策略不一致。

### 发现位置
- `src/appExtracted/appGraphMeasurementFactories.tsx:4822-4826`

### 证据
代码审查。弹窗内测点不可直接编辑（位置移动时按规范公式重算 `:4763`），正常流程难以新造重复；但历史重复数据可经弹窗确认继续留存，且弹窗是测点数据的完整写入入口。

### 风险
低概率保留重复测点；重复测点是运行时绑定 key，可能导致实时值绑定异常。

### 为什么不能自动修改
属新增 UI 校验行为（功能补全），非确定性 bug 修复；错误提示的展示方式需产品确认。无法证明 100% 无副作用。

### 人工处理建议
在 confirm 校验中补充 sourcePoint 查重（drafts 内部 + 与该节点现有其他组），提示方式对齐名称重复的 `showGlobalMessage`。推荐优先级：P2。
